# 정보 보안 및 개인정보 보호 지침

## 데이터 분류

모든 데이터는 다음 3단계로 분류한다:

1. **공개(Public)**: 외부 공개 가능 — 마케팅 자료, 오픈소스 코드
2. **내부(Internal)**: 사내 공유 가능 — 내부 문서, 회의록
3. **기밀(Confidential)**: 제한된 인원만 — 고객 개인정보, 소스코드, 재무 정보

기밀 데이터는 반드시 암호화하여 저장하고, 전송 시 TLS 1.2 이상을 사용한다.

## 접근 권한

최소 권한 원칙(Least Privilege)을 따른다. 직원은 업무 수행에 필요한 최소한의 시스템 접근 권한만 부여받는다. 권한 변경(입사/퇴사/부서이동)은 IT팀에 즉시 요청해야 한다.

## 비밀번호 정책

- 최소 12자 이상, 대소문자+숫자+특수문자 조합
- 90일마다 변경 권장 (중요 시스템은 60일)
- 동일 비밀번호 재사용 금지
- MFA(다중 인증)는 모든 외부 서비스에 필수 적용

## 사고 대응

보안 사고(해킹, 랜섬웨어, 데이터 유출)가 의심되면:

1. 즉시 IT 보안팀에 보고 (`security@company.com` 또는 내선 4000)
2. 관련 시스템의 네트워크 연결 차단
3. 침해 범위 파악 후 필요 시 외부 포렌식 업체 호출
4. 개인정보 유출 시 72시간 내 관련 기관 신고

## 클라우드 보안

AWS 사용 시 IAM 정책은 deny-by-default 원칙을 따른다. S3 버킷은 퍼블릭 접근을 차단하고, CloudTrail 로깅을 활성화한다. API 키는 환경변수나 AWS Secrets Manager로 관리하며 코드에 하드코딩하지 않는다.
