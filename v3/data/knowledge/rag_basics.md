# RAG (Retrieval-Augmented Generation) 기술 개요

## 정의

RAG는 LLM이 답변하기 전에 외부 지식 소스에서 관련 정보를 검색(Retrieve)하여
컨텍스트에 추가(Augment)한 뒤 생성(Generate)하는 패턴이다.

## 핵심 구성 요소

### 1. 인제스천 (Ingestion)
- 문서를 청크(Chunk) 단위로 분할
- 각 청크를 임베딩(Embedding)으로 벡터화
- 벡터 DB에 저장

### 2. 검색 (Retrieval)
- 사용자 쿼리를 임베딩으로 변환
- 벡터 DB에서 유사한 청크 검색 (dense retrieval)
- 키워드 검색(BM25)과 결합한 하이브리드 검색 가능
- 검색 결과를 리랭킹하여 최적의 컨텍스트 선택

### 3. 생성 (Generation)
- 검색된 청크를 프롬프트에 포함
- LLM이 근거 기반으로 답변 생성

## 장점

- 최신 정보 반영 (모델 재학습 불필요)
- 환각 감소 (근거 기반 답변)
- 출처 추적 가능 (어떤 문서를 참조했는지)

## 단점

- 검색 품질에 답변 품질이 의존
- 청킹 전략이 중요 (너무 작으면 문맥 손실, 너무 크면 노이즈)
- 벡터 DB 운영 비용
